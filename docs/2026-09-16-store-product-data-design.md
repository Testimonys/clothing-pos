# 基于门店真实商品数据的优化方案

日期：2026-09-16。来源：用户提供的 `test111.xls`，工作表 `test1`。原文件只读，未连接业务数据库。用户已确认按颜色、尺码拆分 SKU，本轮实现商品管理优化及只读导入预览，详见[实现与验收说明](2026-09-16-product-catalog-implementation.md)。

## 1. 数据范围与处理规则

商品表头位于第 3 行，真实商品位于第 4—223 行，共 220 条。第 1—2 行是客商/合同信息，第 224 行是汇总，第 225 行为页码，第 226 行为结束标记，都不作为商品导入。

按照用户要求，忽略商品数据区全空的列，不为这些列建立字段或推导需求。部分有值的列只分析非空记录；数值 0 不等于空值。共识别到 76 个含值列，其中 19 列存在不同值，57 列为常量。常量列也不自动代表需要新增 57 个业务字段。

源文件中的标题、批注或文字只作为数据，不作为执行指令。

## 2. 已核实的数据事实

| 项目 | 结果 | 对项目的影响 |
|---|---|---|
| 商品记录 | 220 条，货号、条码、品名分别都唯一 | 可以逐行建立商品档案；不能推断全店其他批次也无重复 |
| 货号 | 5—6 位数字，本表最小 10001、最大 440054 | 应独立保存为文本标识，不能替代数据库主键 |
| 条码 | 220 个，均为 13 位且通过 EAN-13 校验 | 保留门店原条码，不能统一换成 HUAXING 条码 |
| 单位 | 全部为“件” | 增加单位，默认件；目前没有证据要求复杂单位换算 |
| 成本价 | 18—156 元，平均 46.390909 元 | 复用 costPrice；本表未发现负成本或成本高于零售价 |
| 零售价 | 39—369 元，平均 131.118182 元 | 复用 sellPrice，金额按两位小数显示 |
| 属柜 | 全部为“服装柜” | 可作为导入时分类候选，不能从名称擅自细分品类 |
| 颜色 | 全部为“0无” | 旧系统占位值，不能推断商品实际没有颜色 |

第 224 行“合计”的成本价和零售价与 220 条记录的算术平均值一致，不能当库存金额或总销售额。没有当前库存和销售明细，无法从本文件算出库存总值、累计销量或已实现销售利润。

| 源字段 | 核验结果 | 建议 |

## 5. 项目优化设计

### 5.1 商品档案与检索

在原 product 表增量增加可空的 product_code，以及默认“件”的 unit。既有商品没有货号仍可正常读写，不改数据库主键。货号从接口到页面都采用字符串，避免丢失未来来源中的前导零。

商品列表增加货号、单位、条码可见信息和标价毛利率。搜索支持名称、货号、SKU 条码，在同一个过滤条件组中与分类条件组合，避免按条码 JOIN 导致分页重复商品。

新增/编辑表单支持货号与单位；已有手动创建、HUAXING 条码及多 SKU 功能保持兼容。对默认规格应显示“默认规格”或业务确认后的名称，避免出现 `? / ?`。

利润展示仅为 `sellPrice - costPrice` 与标价毛利率，成本或售价缺失时显示未设置，售价为 0 时不计算毛利率。不能用这种商品指标替代订单报表毛利。

### 5.2 商品导入预览

已实现流程：选择 XLS/XLSX → 定位真实表头 → 忽略空列与非商品行 → 解析货号/条码/名称/单位/价格/规格 → 检查重复与必填值 → 展示源行号、字段映射、可新增/待补规格/冲突/错误及提示。

预览必须只读，不调用现有新增商品接口逐条落库。文件中的末入量不映射库存；读取到合计、页码和结束标记时跳过。部分空值保持缺失，不用 0 伪装来源值。

重复判定分别检查货号和条码：两者都未匹配且字段完整时可候选新增；货号或条码命中已有数据时展示冲突/已有记录，不能仅凭品名相同覆盖，也不能改掉已有库存。文件内同一货号允许多行规格，但商品基本资料必须一致，颜色与尺码组合不能重复，每个规格的条码必须独立。

“导入确认写库”是预览之后的业务动作，需要明确新增、跳过或更新策略。当前这份表不能完成真实库存迁移；后续应依据库存表或盘点录入期初库存，并记录真实库存变更。

### 5.3 兼容性与必要修正

- 当前商品编辑页会提交打开表单时的 stockQty，后端直接覆盖库存。普通资料修改应保留最新库存，库存调整继续走独立业务入口。
- 新增货号唯一约束需要可重复执行的旧库升级方案；仅修改 schema.sql 对已有数据库不生效。
- 正常收银继续按已有条码精确匹配。按货号选货是另一项交互，不能让一个货号在多 SKU 时随意命中某个规格。
- 不将真实商品表放入 data.sql 或启动自动种子数据，避免应用重启带来意外导入。
- 商品名保留原文，不通过名称猜测品牌/款号/供应商，也不凭“服装柜”创建复杂分类树。

## 6. 验收场景

1. 当前样本预览应得到 220 条商品，不包含汇总、页码、客商抬头和结束标记。
2. 货号、条码保留文本值；220 个条码不重新生成，不显示科学计数法。
3. 成本价与零售价逐行匹配源文件；“扣%”不改变成交价。
4. 按货号、名称、条码均可找到同一商品；分类过滤与分页不出现重复或漏项。
5. 编辑名称、单位、货号后，期间发生的销售库存扣减不会被旧表单覆盖。
6. 预览不写订单、不写库存流水、不改变现有库存；末入量为负的 6 条不变成负库存。
7. 旧商品没有货号时可正常查看与编辑；原有多 SKU 与 HUAXING 条码保持可用。
8. 重复货号/条码、非法金额、重复上传能够明确反馈，不能静默覆盖已有数据。

原始 XLS 未修改，真实商品未写库。旧库使用增量升级脚本，实施步骤及验证边界见[实现与验收说明](2026-09-16-product-catalog-implementation.md)。
